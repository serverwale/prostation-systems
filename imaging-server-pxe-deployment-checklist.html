Imaging Server and PXE Deployment: A Checklist for Labs, Cafes and Offices

An imaging server stores "golden" operating-system images and pushes them to many PCs that boot over the network (PXE). It saves the most time in labs, schools and cafes that re-image often. This is a short checklist; the full guide is ProStation's imaging server and PXE deployment guide. Figures below come from the tools' own documentation; ProStation publishes no imaging benchmarks.

Do you need one?

It usually pays off from roughly a dozen identical machines upward, or whenever you re-image on a schedule, as in labs, exam centres, cafes and schools. For fewer than about ten PCs that rarely change, a reference USB drive is simpler. See the gaming cafe bulk workstation guide and the education industry page for the hardware side of those fleets.

The checklist

ItemWhat to check
PXE bootEnabled in each client's BIOS/UEFI, with network in the boot order, and the PCs on the same segment as the server.
Isolated networkClonezilla's documentation recommends fixed client addresses and an isolated network so images are not sent to unknown machines.
Generalise Windows imagesMicrosoft states Windows images must be generalised with Sysprep before deployment to new PCs.
Unicast or multicastUnicast gives each client its own copy; multicast sends once to a group. FOG notes multicast waits for an expected client count and generally does not cross routers without extra setup.
Tool choiceClonezilla and FOG Project are free. Microsoft says MDT is retired and WDS is deprecated, so do not build a new setup around them.
Image backupRAID is not a backup of your golden images. Keep a copy elsewhere and keep the previous version.

Size the server from bottlenecks

Illustrative arithmetic, not a measurement: a 40 GB image over a 1 Gb/s link (about 125 MB/s at best) takes roughly 5.3 minutes for one client. For 20 clients by unicast on one 1 Gb/s server link, 800 GB leaves the server, about 107 minutes. On a 10 Gb/s server link that falls to about 11 minutes, and multicast sends the image once. Real results are slower because of disk speed, compression and switch limits.

  1. Network link first. See the 1GbE, 10GbE and 25GbE guide.
  2. Storage reads. NVMe handles many parallel reads better than spinning disks. See the NVMe, SAS and SATA guide.
  3. RAM and CPU. Spare RAM helps caching and ECC adds reliability (ECC vs non-ECC). CPU is rarely the first limit.
  4. The client end. A PC with a slow disk or a 1 Gb/s port finishes later than the server could allow.

Frequently asked questions

  • What is PXE boot? — PXE lets a computer start from the network instead of its own disk. The client asks for an address, downloads a small boot environment from a server and runs it, which is how an empty PC can be imaged.
  • Unicast or multicast for a computer lab? — Multicast suits a room of identical PCs imaged together, because the image is sent once. Unicast suits a few PCs arriving at different times. Multicast needs capable switches and usually one subnet.
  • Should I use WDS or MDT? — Microsoft states MDT is retired and WDS is deprecated, so a new setup should look at Clonezilla or FOG, or Configuration Manager or Autopilot if you already use Microsoft's management tools.
  • What server do I need for imaging? — Reason from the network link, storage read speed, RAM and CPU, in that order, and test with your own images. ProStation publishes no imaging benchmarks.
  • Do I need an imaging server for 5 PCs? — Probably not. Under about ten PCs that rarely change, a single reference USB drive is simpler.
